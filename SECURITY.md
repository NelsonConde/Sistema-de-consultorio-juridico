# Política de seguridad

## Reporte de vulnerabilidades

Si identifica una posible vulnerabilidad en el Sistema de Gestión de Casos Jurídicos, utilice el mecanismo privado de reporte de vulnerabilidades de GitHub.

Acceda a la sección **Security** del repositorio, entre en **Advisories** y seleccione **Report a vulnerability**.

Los reportes se remiten de manera privada a los mantenedores del repositorio.

No publique detalles explotables, pruebas de concepto, credenciales ni información sensible en Issues, Discussions o Pull Requests públicos.

## Información del reporte

Para facilitar la evaluación del hallazgo, incluya cuando sea posible:

- Descripción del problema y su impacto potencial.
- Componente y versión o commit afectados.
- Condiciones necesarias para reproducirlo.
- Pasos de reproducción y comportamiento observado.
- Comportamiento esperado.
- Evidencias sanitizadas y medidas de mitigación conocidas.

No incluya contraseñas, tokens, claves API, cookies de sesión, archivos de configuración con credenciales, bases de datos reales ni documentos de usuarios. Sustituya cualquier valor sensible por un marcador de ejemplo.

## Tratamiento de vulnerabilidades

Los reportes se evaluarán de manera privada para determinar su alcance, impacto y medidas de mitigación.

Las correcciones deberán incorporar las verificaciones técnicas correspondientes y revisión independiente antes de integrarse.

La divulgación pública de detalles técnicos se coordinará mediante el mecanismo de avisos de seguridad de GitHub, procurando evitar la exposición de vulnerabilidades sin corregir.

## Versiones afectadas

Al comunicar una vulnerabilidad, indique la etiqueta, versión o commit en el que se observó el problema.

La existencia de una etiqueta de Git no garantiza que corresponda a una versión desplegada en producción.
